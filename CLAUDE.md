# PaxVelo site: technical notes

Single Go program (stdlib only, no DB, no third-party code). Pages, templates, CSS, fonts and images are embedded in one binary. State lives in `data/paxvelo.json` (written on every change); uploads in `data/media`, minutes in `data/files`, Instagram cache in `data/instagram`, stats in `data/stats.json` (counts only, saved each minute, not backed up). Board-facing docs are in README.md; keep it short and non-technical.

## Run / test
- Go 1.22+. `cp paxvelo.conf.example paxvelo.conf`, set `ADMIN_PASSWORD` (12+ chars), leave `SMTP_HOST` empty (emails go to the log, admin password links show on screen). `go run .` → http://localhost:8080, admin at `/admin`. `go test ./...` is what CI runs.

Home: the hero fills the screen on phones (`100svh` minus the header) and about two thirds of it from 768px (68svh, 460–780px) with an uppercase headline; from 1100px it shows the next ride in its corner (`hero-next`, `view.NextRide` = first uncancelled `Upcoming`), each band puts its `.band-head` (label + heading, wrapped in content.go so a missing label changes nothing) left and its first paragraph right (Become a Member: words left, plans right), Next Rides is one row of 4, a heading with no paragraph takes the full width, the photo row shows 4 at a time, Ride With Us / Giving Back put each photo beside its words (same height), Instagram's heading sits beside square posts, the footer puts link columns and sponsors on one row; bands ~72px apart on phones, ~48–72px on computers, text ≤36rem; from 1440px the root font grows (17px, 18px and `--max` 1320px at 1900px); Ride With Us / Giving Back and the photo row are flat (no cards, square corners). A `^^ Label` line right above a `##`/`###` heading renders `<p class="label">` over it (content.go). The hero video pauses when under 15% of it is on screen (site.js).
- **No explaining (Karl's rule), on every page the site builds**, public or admin (forms, tools, calendar, membership, subscribe…): a title, labels, buttons, data and short tooltips (`title`); no lead paragraphs about how a feature works, no muted footnotes, no "how it works" sections. If it needs words to make sense, change the design. Only real alerts (errors, things needing attention) and short empty states. The club's own written pages (`content/*.md`) are not covered; admin explanations live only on How the site works.
- `web/templates/*.html` (admin: `admin.html`, `admin-email.html`, `admin-treasurer.html`), `web/static/site.css` (colors at top), `site.js` (also the stats beacon), `web/static/img/` (logo, favicon, og). `web/waiver.html` and `web/waiver-guardian.html` are legal text copied from the League of American Bicyclists: change only for a new League version; `web/waiver-loaner.html` is the club's own loaner bike agreement (insurer or lawyer approves changes); signed waivers keep their original text (`waiver_texts`).

Home page: `<source media>` picks phone (≤767px) or computer; no phone video = phones play the computer one cut to fit, no computer video = computers show the top photo. Browsers that can't play AV1 (older iPhones/Macs), data saver, and a computer with only a phone video keep the still under it (site.js removes the `<video>` when no source `canPlayType`); reduced motion gets the top photo. Off = the top photo. `cleanVideoFiles` at startup deletes every file in the video folder no video uses (older versions' clips and loops) and the uploads folder. ffmpeg/ffprobe: `FFMPEG` env names ffmpeg if it isn't on PATH; deploy/setup.sh installs it; the page warns when it's missing.

Admins can replace the home page's top photo on Website → Home photos → Top photo (`hero.go`, `Store.Hero`; one upload with one framing for every screen; phones get `Hero.Phone`, an 800px square cut at the framing by `heroPhoneCrop`, remade on each save and at startup if missing; empty = the built-in hero files).

## Behaviors worth knowing
- **Admins:** email + password (PBKDF2). Setup password `ADMIN_PASSWORD` works by name until the first admin sets a password; afterwards it is only an emergency key (logged as `admin login with the setup password as …`). **Levels** (`permissions.go`): website admin (rides/calendar, ride-and-event emails only: `sendAll` forces `topic=events`, photo review/gallery, minutes view, read-only member lookup incl. emergency contact, own spending requests and receipts), board (everything else: routes wrapped in `a.boardOnly`, incl. deleting members/waivers, automations, club PIN) and president (`a.president`: Board page save, add/remove admins, send admin links, backup). Template flags `IsBoard`/`IsPresident` are set in `renderAdmin`; the menu drops `boardTabs` for website admins. `TestAdminRoutesHaveALevel` fails if a new `/admin` route uses plain `a.auth` without being listed in `websiteAdminRoutes`. **Board roles** (`boardroles.go`) come from Website → Board: each `BoardMember` can be tied to a member record (`Member` id, picked in a "Member" select that marks admins with a gold crown (`crown` in icons.go; the select uses `appearance:base-select` where supported, else a plain ♛); the name shown on the page stays separate, e.g. "Gabe" for Gabriel). An admin holds a role when the tied member's email or name matches theirs (untied: the Board page name matches); `linkBoard` tied same-name people once (`BoardLinked`). Anyone on the board, the president or the setup password sees the Treasurer tab (`canSeeMoney`; routes use `a.boardOnly`, others go Home with `err=board-only`); a role containing "Treasurer" or the president removes its lines and saved reports (`canRemoveMoney`, `a.treasurerOnly`). The Admins page shows each admin's roles as tags. The president's own powers stay with Make president. Sessions last 30 days; removing an admin or changing a password logs them out.
- **Card editor** (the page editor's default, "Easy editor"): `cardEditor()` in the `page-edit` template parses the Markdown into cards (settings, title, paragraph, section heading, columns from `###` runs, photos, buttons, lists, ride details, notes, club pieces like `{membership-plans}`) and writes it back into the same textarea, so saving/preview/GitHub are unchanged. Cards keep their original lines until edited (untouched pages save byte-for-byte); anything it can't represent becomes a raw "Text" card. Paste keeps only bold/italic/links. Round-trip check in the browser console on an edit page: `f=document.getElementById('page-form').cards; f.text(f.parse(src))===src`, and `f.rewrite(f.parse(src))` should preview the same. "Edit as text" switches to the old editor (remembered per browser).
- **Page editor** (Website → Pages, "Edit as text"): toolbar types the Markdown marks (Bold, headings, lists, link box, Insert… for columns/fact tables/placeholders), Ctrl+B/I/K/S, unsaved-changes warning. Live preview posts the text to `/admin/pages/<file>/preview`, which draws the page with the real templates minus scripts and animations into a sandboxed frame; nothing is saved.
- **Uploads:** JPG/PNG resized to ≤2000px, EXIF stripped, saved as JPG (PNG with alpha stays PNG); WebP/GIF kept. Max 20 MB; every upload box shrinks photos in the browser first (`web/static/photos.js`, inlined into site.js's page script and the admin pages), so big iPhone photos go up as ~2000px JPEGs. Server keeps ≤2000px at quality 86 (steps down to 1800/1600 past 800 KB). Gallery adds 1440/960/480 copies (missing ones made at startup, `sizeOldPhotos`).
- **Photo framing** (`focus.go`): cropped photos store `"x% y%"` or `"x% y% zoom"` (zoom 1–4); `focusStyle` draws it (object-position, plus scale + clip-path when zoomed; rounded boxes set `--r` in site.css). One admin tool everywhere: `openFraming` in admin.html (drag, zoom, live previews of each shape in `FRAME_SHAPES`; `framingStyle` mirrors `focusStyle`). Used by home photos, board, newsletter photos/strips, gallery photos (`focus-<id>`, autosaved), and page photos (`![alt](photos/x.webp#focus=40,30,1.5)`).
- **Minutes:** uploaded on admin Minutes; listed at `/minutes` (unlinked, noindex: open to anyone with the link, `/minutes#m<id>` per meeting, Copy link in admin). Word uploads become PDFs via headless LibreOffice when installed (`docpdf.go`; profile in `data/office-profile`); the .docx is kept as `original`; Word files from before are converted at startup.
- **Member photos** (`/share-photos`): spam checks (honeypot + form token), 5 sends/hour/IP, queue cap 300, stored in `data/submitted`, reviewed at Website → Photos to review (one card per sender, all ticked; Approve/Reject in place with Undo; rejected kept 30 days, purged when the page opens). **The gallery is the photo library:** the newsletter editor's, Board page's and Home photos' (top photo and photo row) "Choose from the gallery" (`/admin/gallery/pick`, `/admin/newsletter/from-gallery`) and an album's "Add to newsletter" copy photos into an issue (own copy, so removing from the gallery never breaks a sent issue). Public wording is always "Share your photos". **Albums** (Website → Gallery): dragged into order, one can be featured (`Album.Featured`, shown first and big on `/gallery`), and hidden ones (`Album.Hidden`) are off `/gallery`, their pages, the sitemap and the share page's album list but stay in the newsletter's picker. List toggles answer in JSON with the list re-rendered (`album-list` template) and an Undo; an album's captions and order save as they change. **Club PIN** (Security → Club PIN & access) skips review for photos and ride submissions; 10 tries/hour/IP; also lets ride leaders step down/cancel.
- **Rides:** weekly rides, one-offs, event types, levels (Social/Intermediate/Elite), pace groups with leaders. **Events** (meeting, social or party, clinic, other: `CalRide.Kind`) have a host instead of pace groups; members can add them on `/calendar/new`, Strava imports guess the kind from the title (`guessKind`, new events only), and an issue's "Event from the calendar" block (or the event's admin page → Add to newsletter) shows one live from the calendar; it then drops out of the rides block. "Add to my calendar" (`rideICS`) and the search-engine data last `RideOcc.Length` (`ridelength.go`): 18 mph + 30 min per 20 miles from the Strava route or "40 miles" in the name/details, rounded up to 15 min; unknown distance or an event = 2 h. The Strava sync never cancels today's rides (Strava drops started events from "upcoming"). **Virtual rides** (`Virtual`: "yes"/"no" from the box, empty = automatic via `guessVirtual`: Zwift, virtual, trainer ride in the name, place or description) get a Zwift badge on the calendar, or a plain "Virtual" label when `ZwiftLogo` is "no" (box, or automatic via `guessZwift` when another app like Rouvy or Zoom is named); the forms' hidden `virtual_was` keeps automatic unless the box is changed. **Community rides** (`CalRide.Unofficial`/`RideSeries.Unofficial`): `/calendar/new` asks "Is this a PaxVelo event?" (required, `official=yes|no`); No (or the admin forms' "Community (not a PaxVelo event)" box, or the API's read-only `community`) shows a green "Community" tag on the calendar, next rides and admin lists, a note on the ride page, a line in the feed, and drops loaner bikes (`loanerOpen`), the Waiver code button and the First club ride tick. No rider sign-in. New rides without the PIN wait for approval. Ride emails go to `RIDES_EMAIL` (default PaxVeloClub@gmail.com). Public API: `GET /api/rides?from=&to=`; `PUT/DELETE /api/rides/<id>` and `POST /api/strava/sync` need `Authorization: Bearer $CALENDAR_API_KEY`.
- **Calendar subscription** (`calfeed.go`): `/calendar/feed.ics` is the whole calendar for phone calendars to subscribe to (14 days back to a year ahead, one event per ride with the same UID as its "Add to my calendar" file, both from `rideEvent`; no waiting rides; a cancelled ride stays as "Cancelled: …" with no `STATUS:CANCELLED`, since Google drops those). Nothing is kept about who subscribes. `/calendar/subscribe` (noindex) has the buttons: Apple (`webcal://`), Google (`render?cid=webcal…`), Outlook, the visitor's own first (`appleDevice`), plus the address to copy. Linked from the calendar page, My Membership and `{calendar_link}` in emails (email apps don't open `webcal://`); the default welcome email has it (`welcomeCalendar`; `staleWelcome` upgrades an unchanged older default). Phones re-read on their own schedule (Google up to a day), so it isn't a same-morning cancellation notice.
- **Ride status** (`ridestatus.go`): a leader (name + club PIN, Leading this ride? → Ride is on / Cancel this ride / Put it back, optional note ≤120 chars) or an admin (ride admin page, same `/cancel` route with `status=on|cancel|open`; the older `cancel=1|0` still works) sets `CalRide.On`/`Cancelled` with `StatusNote`, `StatusBy`, `StatusAt`. Shown as a green/red banner on the ride page, an "On" chip or "Cancelled · note" in the next rides (home, `upcomingTpl`), the calendar (`cal-lead`, hover card) and the admin list, and in the feed's description. `IsOn` ends with the ride's day. A ride cancelled for today or tomorrow stays in the next rides, struck through (`upcomingRides`). Cancelling emails the club with the note (once, not on a second cancel). Putting it back clears note and On. The Strava import never touches `Cancelled` (Strava events aren't marked cancelled, so it used to undo website cancellations hourly); the calendar API still sets it.
- **Ride routes** (`rideroute.go`): `CalRide.RouteID` / `RideSeries.RouteID` (a weekly ride's dates follow it), set from a "Strava route" box (`parseRoute`: a strava.com/routes link or its number; `<datalist id="club-routes">` offers `ClubRoutes`) on the public add-a-ride form, the leader's panel (`/calendar/ride/{key}/route`, name + PIN) and the admin ride and weekly forms. `withRoute` uses it, else the Strava event's route. Read from Strava right away when connected (`readRouteSoon`) and hourly (`rideRouteIDs` first). Ride page: "21 mi · 400 ft" in the lead line (`RouteStats`), the route row, or "On Strava" before it's read (`RouteOnStrava`); private routes show nothing.
- **Forecast** (`weather.go`): api.weather.gov (no key; `User-Agent` names the site) hourly forecast at each ride's start for the next 6 days (the Strava event's pin, else Leonardtown 38.2912,-76.6355; no time = 9 am; not virtual or cancelled), read every 30 min by `weatherLoop` (points → `forecastHourly`, cached in memory), shown on the ride page from the cache (`ride-weather`: "8 AM 61°F · Mostly Sunny · 20% rain · wind SW 5 to 10 mph"). Not started when SITE_URL is localhost (`localSite`), so previews don't call it.
- **QR codes** (`qr.go`, own encoder: byte mode, level M, versions 1–10; format/version words checked against the ISO tables, Reed–Solomon by syndromes; `QR_OUT=dir go test -run QRLayout` writes sample SVGs to scan). Template func `qr path label` (SITE_URL + path). `/qr/{join|ride-waiver|calendar}` fills a phone screen (ride pages' **Waiver code** button links `/qr/ride-waiver`); Rides → **Signs to print** (`/admin/signs`, every admin) prints one sign per sheet (`qrSigns` in signs.go).
- **I'm in** (`imin.go`; meant to replace Strava RSVPs): a group ride's page (not past, cancelled or waiting: `canJoin`) has a Who's going section: name, pace group (when several), optional email "for changes", First club ride tick (honeypot + form token, 20/hour/IP, 100 per ride). `CalRide.Riders` (`RideRider`: ID, Name, Email, Group, First, Device, Added). The browser gets an HttpOnly `pv_rider` cookie (random, path `/calendar`, 400 days); the data keeps only `deviceHash` (secret-salted), which marks "You're in" + **Can't make it** (`/out`) and fills the name next time (`RiderByDevice`). Public: `ShortName` chips and the count (also `Meta` "N going", which falls back to the Strava count); never emails. A first ride emails the club inbox ("First ride: …") and shows **Sign the ride waiver**. `applyStatus` → `mailRiders`: cancelled / back on emails to riders with an email (kind "Ride change", `SendDirect`). Admin ride page lists riders with emails, Remove (`/admin/rides/{key}/riders/{id}/remove`). `tidyRiders` at startup drops emails and device codes 30 days after the ride.
- **Ride alerts** (`push.go`, `pushcrypto.go`; web push with stdlib crypto only): the bell **Ride alerts** button (`push-btn` template, on the calendar and ride pages; site.js shows it on every browser and a tap opens the `push-panel`: **Notify this phone** where `PushManager` exists and notifications aren't denied (on an iPhone only once the site is on the home screen), then once on ("Alerts on") the **Ride changes** and **Club news** switches and Turn off alerts; and everywhere a **Cancellations by email** box, see Ride alert emails; plain inputs, no `<form>`, since the panel sits inside a `<p>`) subscribes with the site's VAPID key (`Store.PushKey`, P-256, made once; `/push/key`) and posts the subscription to `/push/subscribe` (same origin, 30/hour/IP; only `fcm.googleapis.com`, `android.googleapis.com`, `*.push.apple.com`, `*.push.services.mozilla.com`, `*.notify.windows.com` over https, so the site never posts to an address a visitor picked; cap 5000). Nothing ties a phone to a member (`Store.PushSubs`: endpoint + keys + added + `NoChanges`/`NoNews`); the backup download leaves key and phones out. **Topics** (`topicChanges`, `topicNews`; `PushSub.Wants`): both on by default, stored as what was turned off so phones from before topics get both; the switches post `{endpoint, topics}` to `/push/topics` (same origin, 60/hour/IP; `{endpoint}` alone reads them; an endpoint the site doesn't have is a 404 and site.js turns alerts off on that phone); re-subscribing keeps the choice, and sw.js's `pushsubscriptionchange` sends `old` so it moves to the new address. `applyStatus` → `alertRide`: a cancellation ("Cancelled: name", day, time · note) or a put-back ("Back on: name") of a ride today or later, not held, goes to every phone with Ride changes on (`pushAll(m, ttl, topic, done)`, background, 4 at a time; `Topic` = ride key so a newer alert replaces an older one; TTL until the ride starts, 1–48 h); 404/410 answers forget the phone. Encryption is RFC 8291 aes128gcm (checked against the RFC's worked example in pushcrypto_test.go), signing RFC 8292 ES256 with `sub` = SITE_URL. sw.js shows it (`badge.png` = white PV for Android's status bar) and opens the ride on tap; `pushsubscriptionchange` re-subscribes. **Send an alert** (`pushalerts.go`, Email → Send an alert, board only): title ≤60, message ≤180, Opens = home, the calendar, a ride/event of the next 5 weeks, or another page (`alertLink`: a `/path` on this site, a full SITE_URL address becomes its path, anything else refused); a live notification preview; **Send to N phones** goes to phones with Club news on (TTL 24 h, tag `news-<id>`). At most 5 a day (club time, `alertsPerDay`), counted in `AddPushAlert` before sending; none sent and none counted when no phone has Club news on. `Store.PushAlerts` keeps the last 50 (when, who, title, message, link, phones, reached once done), listed on the page. Listed on Email → Automations as "Ride alerts" with the phone count per topic. The in-app browser pane can't test it (no push in private windows): test on a phone.
- **Ride alert emails** (`alertmail.go`, `Store.AlertEmails`, `alerts.html`): the panel's email box posts JSON to `/alerts/subscribe` (same origin, honeypot `website`, 5/hour/IP, 3/hour/address, cap 3000; same answer for any address) and emails a Confirm link (`/alerts/email?t=`; GET only shows the button, POST confirms; unconfirmed ones are dropped after 7 days). `applyStatus` → `mailAlerts`: the same cancellations and put-backs as the phones go to confirmed addresses, one at a time with `SEND_DELAY` (kind "Ride alert"), skipping riders on that ride with the same address (they get `mailRiders`). Each has a Stop link as its Unsubscribe (`SendAlert`; `/alerts/email?t=&stop=1`, Gmail's one-click posts to it). Nothing ties an address to a member; counted on the Automations "Ride alerts" row. The calendar API's `cancelled` sends neither phones nor emails.
- **Home screen app** (`app.go`, `web/static/sw.js`): `/manifest.webmanifest` (standalone, icons `app-192.png`/`app-512.png` used as any and maskable; `apple-touch-icon.png` 180px; a close-up of logo-light.svg on tarmac.jpg, the stripes running off both edges, drawn with headless Edge; shortcuts Calendar, My Membership, Ride Waiver). The service worker is `/sw.js` (no-cache; `__V__` = site version, a new version empties its caches), registered by site.js: pages come from the network first and a copy is kept (newest 40) only for public pages with no query but `?m=`; `PRIVATE` in sw.js lists what's never kept (admin, membership, RSVP, kit, forms, token links). With no signal: the kept copy, else `/offline` (saved at install). Versioned `/static/` files are kept too. It's the base for push notifications.
- **Admin app** (`adminapp.go`, `admin-app` template, `.app-*` in admin.css): admin pages link `/admin-app.webmanifest` (outside `/admin`: browsers fetch manifests without cookies; scope `/admin`, start `/admin/app`, "PV Admin", black-P icons `admin-192/512.png`, `admin-touch-icon.png`, drawn like the public icon but logo.svg on white), so adding an admin page to the home screen gives a separate app. `/admin/app`: Needs you (`attentionFor`), next 3 rides, then button rows on a dark page (`appTiles`, groups of 3 with badges, each group its own color via `Key` → `.g-rides` etc.; `boardHref` drops board screens for website admins). In standalone mode `/admin` jumps to `/admin/app` and every admin screen swaps `.bar` for the `.app-top` Home bar. **Admin alerts** (`adminpush.go`, `Store.AdminPush`): "Alerts on this phone" at the foot of the app home (buttons first, then Needs you, Next rides): Turn on alerts registers `/admin/sw.js` (the same script as `/sw.js`, scope `/admin/`, so the admin app has its own subscription apart from the club app's ride alerts) and posts to `/admin/push/subscribe`, tying the phone to the logged-in admin (`AdminPushSub.Admin`; the setup password gets no Alerts section, 403); switches per kind (`adminAlertKinds`: requests, rides (held rides + loaner requests), photos, members (board only, `boardOnlyKinds`); `Off` = turned off) post to `/admin/push/kinds`; only the owner can read/change/forget a phone. Sent by `alertAdmins(kind, m, ttl, who)` through `pushSend` with `Icon` admin-192: `alertHeldRide` (calendar.go), `alertLoaner`, `alertPhotos` (only photos going to review), `alertRequestSent` (only `wantsAnswer` admins), `alertRequestSettled` (the sender, from `mailRequestSettled`), `alertSignup` (public.go). `pushsubscriptionchange` posts to `/push/subscribe` with `old`; an admin phone is moved there (`MoveAdminPush`) instead of becoming a ride-alert phone. `DeleteAdmin` forgets their phones; backups leave them out. The browser pane can't test push: test on a phone.

## Calendar API
```sh
curl "https://www.paxvelo.club/api/rides?from=2026-11-01&to=2026-11-30"   # rides as JSON, leaders included
# Add or update a ride; the id is your own name for it (send again to update).
curl -X PUT https://www.paxvelo.club/api/rides/coffee-2026-11-07 -H "Authorization: Bearer $CALENDAR_API_KEY" \
  -d '{"date":"2026-11-07","time":"08:30","name":"Coffee Ride","place":"Leonardtown Square","groups":["Fast","Social"],"strava_url":"https://www.strava.com/clubs/10197/group_events/123"}'
curl -X DELETE https://www.paxvelo.club/api/rides/coffee-2026-11-07 -H "Authorization: Bearer $CALENDAR_API_KEY"   # or cancelled, if leaders signed up
curl -X POST https://www.paxvelo.club/api/strava/sync -H "Authorization: Bearer $CALENDAR_API_KEY"   # import Strava events now
```
Ride fields: `date` (required), `name` (required), `time` (24-hour), `place`, `details`, `groups` (each gets a leader), `strava_url`, `cancelled`. API changes keep leaders who signed up on the website.

## Deploy
- **Cloudflare CDN** (optional): with the DNS record "Proxied", `deploy/Caddyfile` makes Caddy take the visitor's address from `CF-Connecting-IP` only on connections from Cloudflare's ranges (`trusted_proxies static …`, refresh from cloudflare.com/ips) and pass it as the one `X-Forwarded-For` value `clientIP` reads; without it every visitor would share Cloudflare's addresses (spam limits, waiver IPs). Needs Caddy ≥2.7 from Caddy's apt source: `deploy/cloudflare-prep.sh` upgrades it and installs the Caddyfile (validates first, keeps a backup, rolls back if the site doesn't answer). Cloudflare SSL mode must be Full (strict); its free plan refuses uploads over 100 MB (long 4K clips on Top video).
- Ubuntu 24.04 server. DNS A records → server. `scp -r deploy root@SERVER:/root/ && ssh root@SERVER 'cd deploy && sh setup.sh'`; then `scp paxvelo.conf root@SERVER:/opt/paxvelo/` and `chown paxvelo` + `chmod 600` it. HTTPS via Caddy (`deploy/Caddyfile`, not copied by deploys: `scp` it to `/etc/caddy/Caddyfile` and `systemctl reload caddy`).
- **CI:** `.github/workflows/publish.yml` runs on pushes to `main`: builds/tests, then uploads and restarts; auto-rolls back if the new version won't start. Needs secrets `DEPLOY_HOST`, `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS` (key authorised for the `deploy` user in `/home/deploy/.ssh/authorized_keys`); variable `SERVER_ARCH=arm64` for ARM. No `DEPLOY_HOST` = check only. Manual: `./deploy/deploy.sh root@SERVER`.
- Served at www.paxvelo.club since Nov 12 2026 (DNS on Cloudflare; Google Workspace MX records kept; registration still at Squarespace until transferred); `deploy/Caddyfile` redirects the old paxvelo.cc addresses to it, so keep paxvelo.cc registered for old links.
- Lock SSH to keys only: `scp deploy/lock-ssh.sh root@SERVER:/root/ && ssh root@SERVER 'sh lock-ssh.sh'` (refuses if root has no key; test a second login before closing).

## Backups
- Nightly data-file copy (30 days) and weekly `media-DATE.tgz` of photos+minutes+receipts (8 weeks; the cron line is written by `deploy/setup.sh`, so an existing server needs `receipts` added to it by hand) in `/opt/paxvelo/backups`. Nightly 3:30 am rclone copy to Google Drive (`deploy/paxvelo-offsite`, cron `/etc/cron.d/paxvelo-offsite`, config `/opt/paxvelo/rclone.conf` with `scope = drive.file`; token from `rclone authorize drive --drive-scope drive.file`, treat as secret). Failures log `BACKUP TO GOOGLE DRIVE FAILED` (`journalctl -t paxvelo-offsite`); nothing emails about it. Admin **Home** warns when the newest nightly copy is over two days old (`BACKUP_DIR` in paxvelo.conf if the folder moves) and when the disk is getting full.
- **Restore:** `systemctl stop paxvelo`, copy `paxvelo-DATE.json` to `/opt/paxvelo/data/paxvelo.json`, `chown paxvelo:paxvelo`, `systemctl start paxvelo` (stop first or the running site overwrites it). Unpack the newest `media-*.tgz` into `/opt/paxvelo/data`.
- Admin "Download a full backup" is president-only, text data only (no photos/files, no signing key).

## Squarespace import
Members → Import from a spreadsheet (CSV with email and name columns); skips duplicates, sends no welcome email. From a Squarespace profiles export it reads `Member Areas` as the plan and works out paid years from `Customer Since`, `Last Order Date` and `Order Count` (one payment a year). A Squarespace **orders** export (`orders.go`, spotted by its `Paid at` + `Lineitem name` columns) instead sets each payer's dues to end a year after their latest membership payment (join day moves to the payment day, first-join year kept; refunded/cancelled/non-membership orders ignored) and adds payers not on the list; the flash names who was added (IDs in the URL, never emails).
