# PaxVelo site: technical notes

Single Go program (stdlib only, no DB, no third-party code). Pages, templates, CSS, fonts and images are embedded in one binary. State lives in `data/paxvelo.json` (written on every change); uploads in `data/media`, minutes in `data/files`, Instagram cache in `data/instagram`, stats in `data/stats.json` (counts only, saved each minute, not backed up). Board-facing docs are in README.md; keep it short and non-technical.

## Run / test
- Go 1.22+. `cp paxvelo.conf.example paxvelo.conf`, set `ADMIN_PASSWORD` (12+ chars), leave `SMTP_HOST` empty (emails go to the log, admin password links show on screen). `go run .` → http://localhost:8080, admin at `/admin`. `go test ./...` is what CI runs.

## Layout
- Go: `main.go`, `site.go`, `public.go` (routes), `store.go` (data file), `config.go` (conf keys), `admin*.go`, `membership.go`/`waivers.go`/`ridewaivers.go`/`household.go`, `rides*.go`/`calendar.go`/`levels.go`/`api.go`/`loaners.go`, `strava*.go`/`routegroups.go`/`history.go`, `newsletter.go`, `gallery*.go`/`sharephotos.go`/`photo.go`, `instagram.go`/`instafeed.go`, `mail.go`/`emailfmt.go`/`emailcount.go`, `stats.go`, `clubpin.go`, `minutes.go`, `treasurer.go`/`treasureradmin.go`/`boardroles.go`/`requests.go`/`requestsadmin.go`/`requestguess.go`/`requestanswer.go`/`requestreminders.go`.
- `content/<page>.md` = pages (add a file = add a page; `##` headings get anchors; `fold: yes` makes each `##` section tap-to-open on phones, used by Our Rides). Admin edits override the GitHub version (revert per page). Formatting: `content/README.md`. Placeholders: `{strava}`, `{kit}`, `{pay_link}`.
- `web/templates/*.html` (admin: `admin.html`, `admin-email.html`, `admin-treasurer.html`), `web/static/site.css` (colors at top), `site.js` (also the stats beacon), `web/static/img/` (logo, favicon, og). `web/waiver.html` and `web/waiver-guardian.html` are legal text copied from the League of American Bicyclists: change only for a new League version; `web/waiver-loaner.html` is the club's own loaner bike agreement (insurer or lawyer approves changes); signed waivers keep their original text (`waiver_texts`).
- Photos: `content/photos/hero.webp` (~2000px, plus square `hero-phone.webp`), `ride.webp`, `giving.webp` (~1000px). Admins can replace the home page's top photo on Website → Home photos → Top photo (`hero.go`, `Store.Hero`; one upload with one framing for every screen; phones get `Hero.Phone`, an 800px square cut at the framing by `heroPhoneCrop`, remade on each save and at startup if missing; empty = the built-in hero files).
- Config keys (all in `paxvelo.conf`, see example): `SITE_URL ADMIN_PASSWORD DUES_INDIVIDUAL DUES_FAMILY PAYPAL_INDIVIDUAL_URL PAYPAL_FAMILY_URL KIT_URL STRAVA_URL DONATE_URL STRAVA_CLIENT_ID STRAVA_CLIENT_SECRET RIDES_EMAIL CALENDAR_API_KEY SMTP_* FROM_NAME FROM_EMAIL REPLY_TO SEND_DELAY EMAIL_DAILY_LIMIT LISTEN DATA_DIR TIMEZONE`.

## Behaviors worth knowing
- **Admins:** email + password (PBKDF2). Setup password `ADMIN_PASSWORD` works by name until the first admin sets a password; afterwards it is only an emergency key (logged as `admin login with the setup password as …`). **Levels** (`permissions.go`): website admin (rides/calendar, ride-and-event emails only: `sendAll` forces `topic=events`, photo review/gallery, minutes view, read-only member lookup incl. emergency contact, own spending requests and receipts), board (everything else: routes wrapped in `a.boardOnly`, incl. deleting members/waivers, automations, club PIN) and president (`a.president`: Board page save, add/remove admins, send admin links, backup). Template flags `IsBoard`/`IsPresident` are set in `renderAdmin`; the menu drops `boardTabs` for website admins. `TestAdminRoutesHaveALevel` fails if a new `/admin` route uses plain `a.auth` without being listed in `websiteAdminRoutes`. **Board roles** (`boardroles.go`) come from Website → Board: each `BoardMember` can be tied to a member record (`Member` id, picked in a "Member" select that marks admins with a gold crown (`crown` in icons.go; the select uses `appearance:base-select` where supported, else a plain ♛); the name shown on the page stays separate, e.g. "Gabe" for Gabriel). An admin holds a role when the tied member's email or name matches theirs (untied: the Board page name matches); `linkBoard` tied same-name people once (`BoardLinked`). Anyone on the board, the president or the setup password sees the Treasurer tab (`canSeeMoney`; routes use `a.boardOnly`, others go Home with `err=board-only`); a role containing "Treasurer" or the president removes its lines and saved reports (`canRemoveMoney`, `a.treasurerOnly`). The Admins page shows each admin's roles as tags. The president's own powers stay with Make president. Sessions last 30 days; removing an admin or changing a password logs them out.
- **Card editor** (the page editor's default, "Easy editor"): `cardEditor()` in the `page-edit` template parses the Markdown into cards (settings, title, paragraph, section heading, columns from `###` runs, photos, buttons, lists, ride details, notes, club pieces like `{membership-plans}`) and writes it back into the same textarea, so saving/preview/GitHub are unchanged. Cards keep their original lines until edited (untouched pages save byte-for-byte); anything it can't represent becomes a raw "Text" card. Paste keeps only bold/italic/links. Round-trip check in the browser console on an edit page: `f=document.getElementById('page-form').cards; f.text(f.parse(src))===src`, and `f.rewrite(f.parse(src))` should preview the same. "Edit as text" switches to the old editor (remembered per browser).
- **Page editor** (Website → Pages, "Edit as text"): toolbar types the Markdown marks (Bold, headings, lists, link box, Insert… for columns/fact tables/placeholders), Ctrl+B/I/K/S, unsaved-changes warning. Live preview posts the text to `/admin/pages/<file>/preview`, which draws the page with the real templates minus scripts and animations into a sandboxed frame; nothing is saved.
- **Uploads:** JPG/PNG resized to ≤2000px, EXIF stripped, saved as JPG (PNG with alpha stays PNG); WebP/GIF kept. Max 20 MB; every upload box shrinks photos in the browser first (`web/static/photos.js`, inlined into site.js's page script and the admin pages), so big iPhone photos go up as ~2000px JPEGs. Server keeps ≤2000px at quality 86 (steps down to 1800/1600 past 800 KB). Gallery adds 1440/960/480 copies (missing ones made at startup, `sizeOldPhotos`).
- **Photo framing** (`focus.go`): cropped photos store `"x% y%"` or `"x% y% zoom"` (zoom 1–4); `focusStyle` draws it (object-position, plus scale + clip-path when zoomed; rounded boxes set `--r` in site.css). One admin tool everywhere: `openFraming` in admin.html (drag, zoom, live previews of each shape in `FRAME_SHAPES`; `framingStyle` mirrors `focusStyle`). Used by home photos, board, newsletter photos/strips, gallery photos (`focus-<id>`, autosaved), and page photos (`![alt](photos/x.webp#focus=40,30,1.5)`).
- **Minutes:** uploaded on admin Minutes; listed at `/minutes` (unlinked, noindex: open to anyone with the link, `/minutes#m<id>` per meeting, Copy link in admin). Word uploads become PDFs via headless LibreOffice when installed (`docpdf.go`; profile in `data/office-profile`); the .docx is kept as `original`; Word files from before are converted at startup.
- **Member photos** (`/share-photos`): spam checks (honeypot + form token), 5 sends/hour/IP, queue cap 300, stored in `data/submitted`, reviewed at Website → Photos to review (one card per sender, all ticked; Approve/Reject in place with Undo; rejected kept 30 days, purged when the page opens). **The gallery is the photo library:** the newsletter editor's and Board page's "Choose from the gallery" (`/admin/gallery/pick`, `/admin/newsletter/from-gallery`) and an album's "Add to newsletter" copy photos into an issue (own copy, so removing from the gallery never breaks a sent issue). Public wording is always "Share your photos". **Albums** (Website → Gallery): dragged into order, one can be featured (`Album.Featured`, shown first and big on `/gallery`), and hidden ones (`Album.Hidden`) are off `/gallery`, their pages, the sitemap and the share page's album list but stay in the newsletter's picker. List toggles answer in JSON with the list re-rendered (`album-list` template) and an Undo; an album's captions and order save as they change. **Club PIN** (Security → Club PIN & access) skips review for photos and ride submissions; 10 tries/hour/IP; also lets ride leaders step down/cancel.
- **Rides:** weekly rides, one-offs, event types, levels (Social/Intermediate/Elite), pace groups with leaders. **Events** (meeting, social or party, clinic, other: `CalRide.Kind`) have a host instead of pace groups; members can add them on `/calendar/new`, Strava imports guess the kind from the title (`guessKind`, new events only), and an issue's "Event from the calendar" block (or the event's admin page → Add to newsletter) shows one live from the calendar; it then drops out of the rides block. "Add to my calendar" (`rideICS`) and the search-engine data last `RideOcc.Length` (`ridelength.go`): 18 mph + 30 min per 20 miles from the Strava route or "40 miles" in the name/details, rounded up to 15 min; unknown distance or an event = 2 h. The Strava sync never cancels today's rides (Strava drops started events from "upcoming"). **Virtual rides** (`Virtual`: "yes"/"no" from the box, empty = automatic via `guessVirtual`: Zwift, virtual, trainer ride in the name, place or description) get a Zwift badge on the calendar, or a plain "Virtual" label when `ZwiftLogo` is "no" (box, or automatic via `guessZwift` when another app like Rouvy or Zoom is named); the forms' hidden `virtual_was` keeps automatic unless the box is changed. No rider sign-in. New rides without the PIN wait for approval. Ride emails go to `RIDES_EMAIL` (default PaxVeloClub@gmail.com). Public API: `GET /api/rides?from=&to=`; `PUT/DELETE /api/rides/<id>` and `POST /api/strava/sync` need `Authorization: Bearer $CALENDAR_API_KEY`.
- **Strava import:** admin Rides → Connect Strava (needs a Strava API app: callback domain = site host, one athlete, paid subscription on the owning account). Hourly sync of club events (reads them like Strava's apps do, not a documented API), daily past-events and Club Routes (`/routes`) imports, History page for admins. Private Strava events are shown in full (notes, start address): the club makes them private only to keep bots out. Private Strava routes stay hidden.
- **Instagram:** via Behold JSON feed (Meta's API route was abandoned). Admin Instagram tab → paste feed URL → Connect. Polled every 3 h (free plan: 6 posts, 1,200 reads/month). Falls back to Instagram embeds for posts outside the feed.
- **Member page** (`/membership?t=`): My Membership is in the main menu and the footer. Opening a member's link sets an HttpOnly `pv_member` cookie (path `/membership`, 400 days, holds their token), so plain `/membership` opens their page on that device; "Sign out of this device" (`POST /membership/forget`) clears it; without it `/membership` asks for their email. A summary at the top shows dues (with the date an admin marked them paid, `Member.PaidOn`), the waiver and their details, each done or to do the same way; forms only below. Its link is in every club email and gets forwarded, so it shows the phone and emergency contact only in part (last 4 digits, first name and initial); boxes left blank keep what's on file. Test emails use the token `test` (`testToken`), whose My membership and Unsubscribe links open a "That was a test email" page. **Email check:** a website joiner, or someone renewing on `/join` after unsubscribing, is `Unconfirmed` and gets a "Confirm your email" email (`sendConfirm`: Confirm button to their page, PayPal link, the next on-the-road rides for their join-form answer). Club emails skip them (`Emailable`) until they confirm: the email's button opens `/membership?t=…&confirm=1`, whose script presses Confirm (`POST /membership/confirm`, redirects back to the page) for them. Loading the link alone never confirms, since email scanners open links. Each confirm email ends with a no-action-needed line for anyone not expecting it, which also turns emails back on for a returning member; so does Turn club emails back on (the link proves the inbox). Paying and Mark paid never wait for it; an admin adding the address confirms it. Confirm and My-link emails go through `SendMine` (My membership link at the foot, no Unsubscribe).
- **Email choices** (`emailtopics.go`): members switch off the Newsletter or Calendar events on their page (`NoNewsletter`, `NoEvents`, autosaved), or Unsubscribe from everything. Each email to members has a `Campaign.Topic`: newsletter for an issue, events when the admin picks About → Rides and events on Email members, none for club news (dues, waivers), which only a full unsubscribe stops. Unsubscribe links carry `&from=<topic>`: the page offers that kind first, and Gmail's one-click stops just that kind.
- **Renewing on `/join`** (`renewal.go`): for an address already on the list nothing typed is used straight away (anyone can type any email). It's kept as `Member.PendingJoin` (30 days) and the address gets "Finish renewing" (Confirm it's me); Confirm applies it: waiver, riders under 18, Family adults, blank details filled in. The form's answer is the same for every listed address ("This email is already on our list."), no name, dues or PayPal button, so it reveals nothing about the member. Admin Members shows "Renewal not confirmed".
- **Dues:** PayPal payment links only; the site never touches card data. Admins press Mark paid. A website joiner's welcome email goes once they're both marked paid and confirmed, in either order (`TakeWelcome`, `welcomeIfDue`); its `{ride_tips}` adds the live "Rides coming up that suit you" list (`ridesFor`). Waivers are yearly (Jan–Dec), drawn or typed signature, minors signed by a parent/guardian, Family members' other adults get private `/membership?t=` links.
- **Member standing** (`memberstanding.go`): admin Members/Home count by dues, not the email list: Current members (dues not expired), Not paid yet (expired, or joined on the website), Email list only (never paid; Squarespace exports include newsletter sign-ups). The president can tick and **Delete them** (waivers are kept; `relinkWaivers` gives them back to whoever is added later with the account email, at startup and on every new member; an email change records the new one on their waivers as `Account`, keeping `Email` as signed), and fix years paid, join date and email status in a member's Membership record box (sends nothing).
- **Site-move email** (`moved.go`): for members who paid on the old site. Members → tick → **Mark paid & send site-move email** (or the member page button) marks them paid if needed and sends it instead of the welcome (`MovedSent` records it). Editable on Email. `{dues_expire}` = `DuesExpire`: the join day, the year after the last year paid; shown on the member list, member page and /membership ("Good through"). **Paid follows the expiry** (`dues.go`): `Member.Paid()` is today ≤ `DuesExpire`; `PaidYears` are membership years from the join day. Mark paid adds `nextPaidYear` (new member: a year from joining; lapsed: the year ending 6–18 months out); "Renew early" on a member page adds a year; Undo removes the latest year. Join days use `TIMEZONE` (`clubTZ`). Waivers stay Jan–Dec.
- **Club kit** (`kit.go` store, `kitpage.go` public `/kit`, `kitadmin.go` + `admin-kit.html` Website → Club kit, board only): the yearly Jakroo bulk order. `Store.Kit` (`KitShop`): items the board builds (photo, `MemberPrice` = subsidized, `Price` = regular, sizes, hidden; unpriced = not shown; seeded jersey + bibs once), order window (`Open` + `Closes`), `PayURL` (a PayPal.me link gets `/<total>USD` added, `PayLink`), `Round` (Start next year's order; old orders kept, `?round=`). Members order from `/kit?t=<token>` (`{kit_link}` placeholder; **Write the kit email** fills the Email members draft; cookie `pv_kit` on `/kit`; My Membership shows the order while open); only paid-up members (`Member.Paid`) get the form; one `KitOrder` per member per round, lines keep name and price as ordered, changeable until it closes or is marked paid. Admin: Mark paid, totals by item and size (`Tally`), CSV. kit.md's words wrap the store (Intro above, Body below); removing kit.md makes `/kit` the team store again.
- **Ride waivers** (`ridewaivers.go`, `ride-waiver.html`): `/ride-waiver` (noindex; linked from the footer, Our Rides' questions and the free First Ride box in `{membership-plans}` on Home; `/loaner` opens it with the club bike picked) is for first-time riders: name, email, Club loaner bike or My own bike, agree, signature (drawn or typed, `signature-pad`), parent or guardian for a rider under 18. No explanatory text on the page (Karl's rule). Own bike signs the League waiver; loaner signs `waiver-loaner.html` then the League waiver (`forRide`; the loaner text shows by CSS `:has()` once picked); a minor adds the guardian release. Kept as `Store.RideWaivers` (texts in `waiver_texts`), one per signer+rider+bike per club day; honeypot + form token + 10/hour/IP. `MemberID` ties one to the member with that email (at signing, and `linkRideWaivers` on every new member, delete and startup). Admin: Waivers → First rides (per year, CSV), signed copy `/admin/ride-waivers/<id>` (board; Delete), and the member's page lists theirs.
- **Loaner bikes** (`loaners.go`, `Store.Loaners`; Rides → Loaner bikes, every admin): the fleet (`LoanerBike`: size, rider heights, bike, Ready; seeded once with XS 2017 Trek Domane 47 cm and XL 2018 Cannondale Synapse 61 cm ready, M and L empty). Every group ride on the road (not events, virtual, cancelled or waiting rides) shows the ready bikes on its page until 8 pm the day before (`loanerOpen`); taken ones say Reserved. `/calendar/ride/<key>/loaner` is the ride-waiver template in loaner mode: bike, name, email, loaner waiver signed with it (`rideWaiverForm`), 5/hour/IP. A waiting or confirmed request holds that bike for that ride (`bikeHeld`); the club (`Notify`, RIDES_EMAIL) is emailed and Home shows it; admins Confirm / Decline (optional reason) / Cancel, and the rider gets a `mailLoaner` email each time. A bike held for a ride coming up can't be removed.
- **Stats:** counts only by design; no per-member tracking. Weekly visitor codes are salted hashes kept until week end; emails use random per-copy tracking codes not tied to members.
- **Emailing an issue** (`newsletteremail.go`): issue page → Email this issue: preview, Send a test, Send to members (published issues only). `issueEmail` writes the whole issue in email marks (emailfmt.go adds `*italics*`, `^^ kicker`, `---`) and sends it as a campaign tied to the issue (`Campaign.Issue`), leaving the Email members draft alone.
- **Automations** (`automations.go`, `web/templates/admin-email.html`): Email → Automations lists every email the site sends by itself as rows (left edge green = on, red = off, yellow = sent by hand; a switch turns each on or off in place; the site-move row has Send to members, a member list inside the row) that open to details and a preview (fetched into `srcdoc`: the CSP blocks framing our own pages). Built in: Confirm your email (switch off = `ConfirmOff`: new joiners start confirmed; `Store.ConfirmText`, pieces `{confirm_button}` `{pay_line}` `{rides_for_you}` filled by `fillConfirm`; renew/rejoin variants stay in code), Welcome (pausable), Site-move. Admins add their own (`Automation`: trigger from `autoTriggers` + days before/after); `automationLoop` runs every 15 min from 9 am club time, sends to `Emailable()` members once per occurrence (`Sent[memberID]` = the day it follows), only for days on/after it was made and within 7 days (`autoCatchUp`). Remove has Undo (`RemovedAuto`). Every email box uses `mailCards()` (easy editor: cards for paragraph, heading, button, photo, list, line, club pieces; "Edit as text" remembered as `mail-editor`). Round-trip check: `f=document.querySelector('form.mail-form').cards; f.text(f.parse(src))===src`.
- **CSP hashes** (`csp.go`) are taken with line breaks as `\n`, like browsers, so a Windows checkout (CRLF) runs the site's scripts too.
- **Admin look** (`web/static/admin.css` top, `foot` script in admin.html): tokens on `:root` (`--radius`, `--radius-lg`, `--edge`, `--ring`, `--lift`). Three button kinds: primary (`button`/`.btn`, solid red), secondary (`.ghost`), list actions (`.link`, `.link.danger`); all lift on hover, press down, show `--ring` on keyboard focus, fade when disabled. Buttons drawn as something else (`.auto-open`, `.framer-open`, `.switch`, sort headings…) are listed in one `:is(...)` rule that keeps them flat. Feedback: any form send marks its button `.is-busy` (spinner, double sends ignored, reset on back/after 15 s) unless the form's own script stopped the send; the green "Saved" toast closes on click/Escape; errors (`.flash.err`, shake) and warnings (`.flash.warn`) have icons; `:target` rows glow (Undo links use `#id`). `[hidden]` always hides. **No explanatory text** on admin screens (Karl's rule): only labels, data, tooltips (`title`), short empty states ("No albums yet.") and real alerts (test mode, errors, things needing attention); the How the site works page is where explanations live.
- **Drag bars** (`foot` template in admin.html): every preview window (email, automation list, newsletter email, page editor) and anything with `data-resize="name"` gets a `.drag-bar` under it: drag or arrow keys resize, double-click resets; height kept per kind in localStorage (`h:<kind>`). A hand-set height stops `initMail` from fitting the frame to the email.
- **Treasurer** (`treasurer.go` books + report, `treasureradmin.go` pages, `admin-treasurer.html`; `Store.Treasury` in the data file): Expenses / Income / Budget / Reports. Board members only (Website → Board, see Admins). Lines (`LedgerEntry`: kind, date, cents, category, what, who, receipt) are added and edited by any board member; Remove keeps one for Undo (`Treasury.Removed`). Receipts: photo (shrunk in the browser by photos.js, then `shrinkReceipt` to ≤2000px, EXIF gone) or PDF as is, in `data/receipts` (0700), served only at `/admin/treasurer/receipts/<name>` behind login. Categories are Barry's Quicken ones (seeded once, `seedTreasury`); a new one can be typed on the add form; the Budget page renames (lines, budgets and notes follow), reorders, adds and removes them (one with lines stays). **Membership income** = `duesIncome`: every `PaidYears` year counts once on its `PaidOn` day (Mark paid, or the payment day from an orders import) or, with no date (profile imports), the member's join day that year, at today's `DUES_INDIVIDUAL`/`DUES_FAMILY` for their current plan; deleted members drop out, so save reports for meetings. It goes in `Treasury.DuesCat` (Income → "Counted in"; empty = typed in by hand). **PayPal fees** (`PayPalFee`, `Treasury.Fee`; Income → PayPal fee): worked out per dues payment as percent + fixed (default 3.49% + $0.49, `seedFee`), only for payments marked paid on/after `Since` (default the day it shipped, Nov 5 2026: earlier dues went through Squarespace, whose fees were typed in) and not for a site-move payment (`MovedSent` within a day of `PaidOn`); counted as an expense in `Fee.Cat` (default Bank Fees), with membership income kept gross like Barry's report; the Expenses list shows them as a read-only "PayPal fees on dues" row. Budget per year (`BudgetYear`: beginning balance, budget per category — missing = blank, 0 = "$ -" — Notes column per row, numbered notes). `buildReport(through)` lays it out like Barry's monthly report ("PaxVelo Income/Expense by Category", "2026 Budget - YTD Actuals through 7/31/2026"); default through = end of last month; Print (CSS), `/admin/treasurer/report.csv|.md` ("2026-07-31 Monthly Report.csv"); Save for the meeting freezes a copy (`SavedReport`).
- **Spending requests** (`requests.go` store, `requestsadmin.go` page and emails, `requestguess.go` category guess + budget, `requestanswer.go` answer-from-email, `requestreminders.go`; Treasurer → Requests; `Treasury.Requests`): any admin sends "I already bought it" (`reqReport`, a reimbursement) or "I want to buy something" (`reqPurchase`). **Reimbursements are PayPal only** (`payTo`; no PayPal account, no reimbursement; no other method is offered), to `AdminUser.PayPalEmail()`: the "PayPal for reimbursements" email each admin can set on their own Admins entry (`POST /admin/admins/paypal`, blank = login email; shown under their email in the Admins list). Phone-first form, one column on computers too: receipt first (two file inputs both named `receipt`: Take a photo with `capture=environment`, which on a computer (`pointer:fine`) opens the webcam in a `.cam` panel and puts the snapped JPEG into the same input; and Upload a photo or PDF; thumbnail + Remove), amount, what for, optional ride/event (`EventKey/EventName/EventDate`, for the per-event totals coming later), date tucked away (default today). **No category picker:** `guessCategory` (past requests sharing a word, sender's first → category name in the words → `catHints` → sender's last → club-rides category); officers change it on the waiting card (`/category`). Board sees `budgetHint` ("…: $140.00 of $400.00 left in 2026", warns over, never blocks; live via `/requests/guess`); website admins see no budget figures. Duplicate warning (same sender + amount, dates ≤3 days apart) re-renders with Send anyway (`dup_ok`); a receipt uploaded with a form that comes back rides along signed in `kept` (`keptReceipt`). Answers: `Treasurer` (an admin with a Treasurer board role) and `President` (`u.President` or the setup password); the sender's own role is filled in as `Own`. **One answer** (`One`, `oneApproval`): amount ≤ `Treasury.OneLimit` (nil = $50, 0 = always two; "Treasurer alone approves up to" in the Budget page header, `POST /admin/treasurer/budget/one-ok`, board) and ≤ what's left of the category's budget (no budget = two); then only the treasurer's (or the president's when the treasurer sent it: `presidentNeeded`). Recomputed on category change and limit save (`ReweighSpendRequest`, can settle). A rejection needs a reason. **Email answers:** the ask email (`mailRequestAsk`, per approver) has the receipt photo and Approve/Reject linking `/request-answer/<id.admin.expiry.sig>` (HMAC of the store secret, 7 days); GET only shows the request, POST answers (like the member Confirm page), and once their answer is in the link only shows what happened; `/receipt` under it serves the receipt. Admin CSP covers that path. Tracker: "My requests" (`Track()`: Sent → Approved → Paid back / Receipt added; rejected shows the reason). To reimburse list for officers ("Pay Allie $45.00 — PayPal allie@…", Paid); Paid emails a reimbursement receipt to `clubInbox` (PaxVeloClub@gmail.com) only (`mailReimbursed`), never the person paid. Reminders (`runRequestReminders`, from `automationLoop`, 9 am+): approver after 3 days (`Nudged`), Monday to-reimburse list to the treasurer (`Treasury.PayListSent`), purchase receipt after 10 days (`ReceiptNudged`, only within 30 days of approval); all marked before sending; listed as built-in rows on Email → Automations. The treasurer and president are emailed when one arrives (only whoever's answer is wanted, `mailRequest` in the sent log), and the sender when it's settled. Approved = `bookRequest` adds the expense line itself (`LedgerEntry.Request`; a report on its date, a purchase on the approval day), sharing the receipt file (`dropReceipt` keeps files a request shows). An approved purchase gets "Add receipt" (final amount + day + receipt update the line, `BoughtSpendRequest`); an approved report gets "Paid back" (officers). Senders withdraw while waiting (Undo). Home (`attentionFor`) and a badge on Requests show what waits for the logged-in admin; the treasurer also sees reports to pay back.
- **Sent log** (`emaillog.go`): every send (`Mailer.send`) is appended to `data/email-log.jsonl` with kind, recipient, subject and result (never the body); halves itself past 4 MB. Admin Email → Sent log (search, kind, failed only); Home warns about failures in the last 7 days.
- **Email:** Brevo SMTP from `news@paxvelo.cc` (add DKIM/DMARC in Cloudflare DNS; SMTP login looks like `abc@smtp-brevo.com`). Bulk sends pause after 3 straight failures and resume with **Resume**. Failures: `journalctl -u paxvelo | grep failed`. Every email has `Reply-To: PaxVeloClub@gmail.com` (`REPLY_TO`), since `news@` takes no mail; Cloudflare Email Routing could forward it too.

## Calendar API
```sh
curl "https://www.paxvelo.club/api/rides?from=2026-11-01&to=2026-11-30"   # rides as JSON, leaders included
# Add or update a ride; the id is your own name for it (send again to update).
curl -X PUT https://www.paxvelo.club/api/rides/coffee-2026-11-07 -H "Authorization: Bearer $CALENDAR_API_KEY" \
  -d '{"date":"2026-11-07","time":"08:30","name":"Coffee Ride","place":"Leonardtown Square","groups":["Fast","Social"],"strava_url":"https://www.strava.com/clubs/10197/group_events/123"}'
curl -X DELETE https://www.paxvelo.club/api/rides/coffee-2026-11-07 -H "Authorization: Bearer $CALENDAR_API_KEY"   # or cancelled, if leaders signed up
curl -X POST https://www.paxvelo.club/api/strava/sync -H "Authorization: Bearer $CALENDAR_API_KEY"   # import Strava events now
```
Ride fields: `date` (required), `name` (required), `time` (24-hour), `place`, `details`, `groups` (each gets a leader), `strava_url`, `cancelled`. API changes keep leaders who signed up on the website.

## Deploy
- Ubuntu 24.04 server. DNS A records → server. `scp -r deploy root@SERVER:/root/ && ssh root@SERVER 'cd deploy && sh setup.sh'`; then `scp paxvelo.conf root@SERVER:/opt/paxvelo/` and `chown paxvelo` + `chmod 600` it. HTTPS via Caddy (`deploy/Caddyfile`, not copied by deploys: `scp` it to `/etc/caddy/Caddyfile` and `systemctl reload caddy`).
- **CI:** `.github/workflows/publish.yml` runs on pushes to `main`: builds/tests, then uploads and restarts; auto-rolls back if the new version won't start. Needs secrets `DEPLOY_HOST`, `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS` (key authorised for the `deploy` user in `/home/deploy/.ssh/authorized_keys`); variable `SERVER_ARCH=arm64` for ARM. No `DEPLOY_HOST` = check only. Manual: `./deploy/deploy.sh root@SERVER`.
- Currently served at paxvelo.cc while Squarespace keeps paxvelo.club. **Move to .club:** edit first two blocks of `deploy/Caddyfile` and uncomment the redirect block, push the Caddyfile to the server, set `SITE_URL=https://www.paxvelo.club`, restart, repoint DNS, update Strava callback domain, then cancel the Squarespace plan (keep the domain; keep paxvelo.cc for old links). Old Squarespace URLs already redirect.
- Lock SSH to keys only: `scp deploy/lock-ssh.sh root@SERVER:/root/ && ssh root@SERVER 'sh lock-ssh.sh'` (refuses if root has no key; test a second login before closing).

## Backups
- Nightly data-file copy (30 days) and weekly `media-DATE.tgz` of photos+minutes+receipts (8 weeks; the cron line is written by `deploy/setup.sh`, so an existing server needs `receipts` added to it by hand) in `/opt/paxvelo/backups`. Nightly 3:30 am rclone copy to Google Drive (`deploy/paxvelo-offsite`, cron `/etc/cron.d/paxvelo-offsite`, config `/opt/paxvelo/rclone.conf` with `scope = drive.file`; token from `rclone authorize drive --drive-scope drive.file`, treat as secret). Failures log `BACKUP TO GOOGLE DRIVE FAILED` (`journalctl -t paxvelo-offsite`); nothing emails about it. Admin **Home** warns when the newest nightly copy is over two days old (`BACKUP_DIR` in paxvelo.conf if the folder moves) and when the disk is getting full.
- **Restore:** `systemctl stop paxvelo`, copy `paxvelo-DATE.json` to `/opt/paxvelo/data/paxvelo.json`, `chown paxvelo:paxvelo`, `systemctl start paxvelo` (stop first or the running site overwrites it). Unpack the newest `media-*.tgz` into `/opt/paxvelo/data`.
- Admin "Download a full backup" is president-only, text data only (no photos/files, no signing key).

## Squarespace import
Members → Import from a spreadsheet (CSV with email and name columns); skips duplicates, sends no welcome email. From a Squarespace profiles export it reads `Member Areas` as the plan and works out paid years from `Customer Since`, `Last Order Date` and `Order Count` (one payment a year). A Squarespace **orders** export (`orders.go`, spotted by its `Paid at` + `Lineitem name` columns) instead sets each payer's dues to end a year after their latest membership payment (join day moves to the payment day, first-join year kept; refunded/cancelled/non-membership orders ignored) and adds payers not on the list; the flash names who was added (IDs in the URL, never emails).
