# Rides and the calendar

Detailed notes moved from CLAUDE.md. Read the section for the feature you are changing; keep it current when behaviour changes.

- **Rides:** weekly rides, one-offs, event types, levels (Social/Intermediate/Elite), pace groups with leaders. **Events** (meeting, social or party, clinic, other: `CalRide.Kind`) have a host instead of pace groups; members can add them on `/calendar/new`, Strava imports guess the kind from the title (`guessKind`, new events only), and an issue's "Event from the calendar" block (or the event's admin page → Add to newsletter) shows one live from the calendar; it then drops out of the rides block. "Add to my calendar" (`rideICS`) and the search-engine data last `RideOcc.Length` (`ridelength.go`): 18 mph + 30 min per 20 miles from the Strava route or "40 miles" in the name/details, rounded up to 15 min; unknown distance or an event = 2 h. The Strava sync never cancels today's rides (Strava drops started events from "upcoming"). **Virtual rides** (no waiver asks: `AsksWaiver` is false for virtual and community rides, so no First club ride tick, Waiver code button or Sign the ride waiver; `Virtual`: "yes"/"no" from the box, empty = automatic via `guessVirtual`: Zwift, virtual, trainer ride in the name, place or description) get a Zwift badge on the calendar, or a plain "Virtual" label when `ZwiftLogo` is "no" (box, or automatic via `guessZwift` when another app like Rouvy or Zoom is named); the forms' hidden `virtual_was` keeps automatic unless the box is changed. **Community rides** (`CalRide.Unofficial`/`RideSeries.Unofficial`): `/calendar/new` asks "Is this a PaxVelo event?" (required, `official=yes|no`); No (or the admin forms' "Community (not a PaxVelo event)" box, or the API's read-only `community`) shows a green "Community" tag on the calendar, next rides and admin lists, a note on the ride page, a line in the feed, never asks for a leader and its page has no Ride leaders list (only "Leading this ride?" for status/cancel; `leadRide` refuses it) (`Status` "community", `LeaderSummary` = its leaders or blank, left off Needs you and the new-ride email's "still needs leaders"), and drops loaner bikes (`loanerOpen`), the Waiver code button and the First club ride tick. No rider sign-in. New rides without the PIN wait for approval. Ride emails go to `RIDES_EMAIL` (default PaxVeloClub@gmail.com): cancelled or moved rides and anything for today or tomorrow at once, the rest in the Morning summary (`notifyRide(…, urgent)`, `clubNotice`, summary.go; see docs/email.md). **Starting values** (`ridestarts.go`, `web/static/ridestarts.js`, joined to photos.js so the public pages get it in site.js and the admin inline): the Add a ride forms (`/admin/rides/new`, `/calendar/new`) carry `data-starts` (`rideStarts`: per weekday the start time, place, pace menu value and level of the weekly ride on that weekday (group rides only, not ended), else of the latest one-off group ride on that weekday on or before today, else the soonest after; groups the menu can't show are left out) and `data-fresh` on a new form (not after a problem). Picking a date fills only fields that are empty or still hold the form's own value (its 8:00, or what it filled before); a weekday with nothing puts filled fields back as they started; typed fields are never touched. The form's `change` events still fire, so leader rows follow the pace menu. Public API: `GET /api/rides?from=&to=`; `PUT/DELETE /api/rides/<id>` and `POST /api/strava/sync` need `Authorization: Bearer $CALENDAR_API_KEY`.
- **Calendar subscription** (`calfeed.go`): `/calendar/feed.ics` is the whole calendar for phone calendars to subscribe to (14 days back to a year ahead, one event per ride with the same UID as its "Add to my calendar" file, both from `rideEvent`; no waiting rides; a cancelled ride stays as "Cancelled: …" with no `STATUS:CANCELLED`, since Google drops those). Nothing is kept about who subscribes. `/calendar/subscribe` (noindex) has the buttons: Apple (`webcal://`), Google (`render?cid=webcal…`), Outlook, the visitor's own first (`appleDevice`), plus the address to copy. Linked from the calendar page, My Membership and `{calendar_link}` in emails (email apps don't open `webcal://`); the default welcome email has it (`welcomeCalendar`; `staleWelcome` upgrades an unchanged older default). Phones re-read on their own schedule (Google up to a day), so it isn't a same-morning cancellation notice.
- **Ride status** (`ridestatus.go`): a leader (name + club PIN, Leading this ride? → Ride is on / Cancel this ride / Put it back, optional note ≤120 chars) or an admin (ride admin page, same `/cancel` route with `status=on|cancel|open`; the older `cancel=1|0` still works) sets `CalRide.On`/`Cancelled` with `StatusNote`, `StatusBy`, `StatusAt`. Shown as a green/red banner on the ride page, an "On" chip or "Cancelled · note" in the next rides (home, `upcomingTpl`), the calendar (`cal-lead`, hover card) and the admin list, and in the feed's description. `IsOn` ends with the ride's day. A ride cancelled for today or tomorrow stays in the next rides, struck through (`upcomingRides`). Cancelling emails the club with the note (once, not on a second cancel). Putting it back clears note and On. The Strava import never touches `Cancelled` (Strava events aren't marked cancelled, so it used to undo website cancellations hourly); the calendar API still sets it.
- **Ride routes** (`rideroute.go`): `CalRide.RouteID` / `RideSeries.RouteID` (a weekly ride's dates follow it), set from a "Strava route" box (`parseRoute`: a strava.com/routes link or its number; `<datalist id="club-routes">` offers `ClubRoutes`) on the public add-a-ride form, the leader's panel (`/calendar/ride/{key}/route`, name + PIN) and the admin ride and weekly forms. `withRoute` uses it, else the Strava event's route. Read from Strava right away when connected (`readRouteSoon`) and hourly (`rideRouteIDs` first). Ride page: "21 mi · 400 ft" in the lead line (`RouteStats`), the route row, or "On Strava" before it's read (`RouteOnStrava`); private routes show nothing.
- **Forecast** (`weather.go`): api.weather.gov (no key; `User-Agent` names the site) hourly forecast at each ride's start for the next 6 days (the Strava event's pin, else Leonardtown 38.2912,-76.6355; no time = 9 am; not virtual or cancelled), read every 30 min by `weatherLoop` (points → `forecastHourly`, cached in memory), shown on the ride page from the cache (`ride-weather`: "8 AM 61°F · Mostly Sunny · 20% rain · wind SW 5 to 10 mph"). Not started when SITE_URL is localhost (`localSite`), so previews don't call it.
- **QR codes** (`qr.go`, own encoder: byte mode, level M, versions 1–10; format/version words checked against the ISO tables, Reed–Solomon by syndromes; `QR_OUT=dir go test -run QRLayout` writes sample SVGs to scan). Template func `qr path label` (SITE_URL + path). `/qr/{join|ride-waiver|calendar}` fills a phone screen (ride pages' **Waiver code** button links `/qr/ride-waiver`); Rides → **Signs to print** (`/admin/signs`, every admin) prints one sign per sheet (`qrSigns` in signs.go).
- **I'm in** (`imin.go`; meant to replace Strava RSVPs): a group ride's page (not past, cancelled or waiting: `canJoin`) has a Who's going section: name, pace group (when several), optional email "for changes", First club ride tick (honeypot + form token, 20/hour/IP, 100 per ride). `CalRide.Riders` (`RideRider`: ID, Name, Email, Group, First, Device, Added). The browser gets an HttpOnly `pv_rider` cookie (random, path `/calendar`, 400 days); the data keeps only `deviceHash` (secret-salted), which marks "You're in" + **Can't make it** (`/out`) and fills the name next time (`RiderByDevice`). Public: `ShortName` chips and the count (also `Meta` "N going", which falls back to the Strava count, labelled "N going on Strava" there and in the ride page's Strava row); never emails. A first ride tells the club inbox ("First ride: …", in the Morning summary unless the ride is today or tomorrow) and shows **Sign the ride waiver**. `applyStatus` → `mailRiders`: cancelled / back on emails to riders with an email (kind "Ride change", `SendDirect`). Admin ride page lists riders with emails, Remove (`/admin/rides/{key}/riders/{id}/remove`). `tidyRiders` at startup drops emails and device codes 30 days after the ride.
- **Ride alerts** (`push.go`, `pushcrypto.go`; web push with stdlib crypto only): the bell **Ride alerts** button (`push-btn` template, on the calendar and ride pages; site.js shows it on every browser and a tap opens the `push-panel`: **Notify this phone** where `PushManager` exists and notifications aren't denied (on an iPhone only once the site is on the home screen), then once on ("Alerts on") the **Ride changes** and **Club news** switches and Turn off alerts; and everywhere a **Cancellations by email** box, see Ride alert emails; plain inputs, no `<form>`, since the panel sits inside a `<p>`) subscribes with the site's VAPID key (`Store.PushKey`, P-256, made once; `/push/key`) and posts the subscription to `/push/subscribe` (same origin, 30/hour/IP; only `fcm.googleapis.com`, `android.googleapis.com`, `*.push.apple.com`, `*.push.services.mozilla.com`, `*.notify.windows.com` over https, so the site never posts to an address a visitor picked; cap 5000). Nothing ties a phone to a member (`Store.PushSubs`: endpoint + keys + added + `NoChanges`/`NoNews`); the backup download leaves key and phones out. **Topics** (`topicChanges`, `topicNews`; `PushSub.Wants`): both on by default, stored as what was turned off so phones from before topics get both; the switches post `{endpoint, topics}` to `/push/topics` (same origin, 60/hour/IP; `{endpoint}` alone reads them; an endpoint the site doesn't have is a 404 and site.js turns alerts off on that phone); re-subscribing keeps the choice, and sw.js's `pushsubscriptionchange` sends `old` so it moves to the new address. `applyStatus` → `alertRide`: a cancellation ("Cancelled: name", day, time · note) or a put-back ("Back on: name") of a ride today or later, not held, goes to every phone with Ride changes on (`pushAll(m, ttl, topic, done)`, background, 4 at a time; `Topic` = ride key so a newer alert replaces an older one; TTL until the ride starts, 1–48 h); 404/410 answers forget the phone. Encryption is RFC 8291 aes128gcm (checked against the RFC's worked example in pushcrypto_test.go), signing RFC 8292 ES256 with `sub` = SITE_URL. sw.js shows it (`badge.png` = white PV for Android's status bar) and opens the ride on tap; `pushsubscriptionchange` re-subscribes. **Send an alert** (`pushalerts.go`, Email → Send an alert, board only): title ≤60, message ≤180, Opens = home, the calendar, a ride/event of the next 5 weeks, or another page (`alertLink`: a `/path` on this site, a full SITE_URL address becomes its path, anything else refused); a live notification preview; **Send to N phones** goes to phones with Club news on (TTL 24 h, tag `news-<id>`). At most 5 a day (club time, `alertsPerDay`), counted in `AddPushAlert` before sending; none sent and none counted when no phone has Club news on. `Store.PushAlerts` keeps the last 50 (when, who, title, message, link, phones, reached once done), listed on the page. Listed on Email → Automations as "Ride alerts" with the phone count per topic. The in-app browser pane can't test it (no push in private windows): test on a phone.
- **Ride alert emails** (`alertmail.go`, `Store.AlertEmails`, `alerts.html`): the panel's email box posts JSON to `/alerts/subscribe` (same origin, honeypot `website`, 5/hour/IP, 3/hour/address, cap 3000; same answer for any address) and emails a Confirm link (`/alerts/email?t=`; GET only shows the button, POST confirms; unconfirmed ones are dropped after 7 days). `applyStatus` → `mailAlerts`: the same cancellations and put-backs as the phones go to confirmed addresses, one at a time with `SEND_DELAY` (kind "Ride alert"), skipping riders on that ride with the same address (they get `mailRiders`). Each has a Stop link as its Unsubscribe (`SendAlert`; `/alerts/email?t=&stop=1`, Gmail's one-click posts to it). Nothing ties an address to a member; counted on the Automations "Ride alerts" row. The calendar API's `cancelled` sends neither phones nor emails.
- **Ride waivers** (`ridewaivers.go`, `ride-waiver.html`): `/ride-waiver` (noindex; linked from the footer, Our Rides' questions and the free First Ride box in `{membership-plans}` on Home; `/loaner` opens it with the club bike picked) is for first-time riders: name, email, Club loaner bike or My own bike, agree, signature (drawn or typed, `signature-pad`), parent or guardian for a rider under 18. No explanatory text on the page (Karl's rule). Own bike signs the League waiver; loaner signs `waiver-loaner.html` then the League waiver (`forRide`; the loaner text shows by CSS `:has()` once picked); a minor adds the guardian release. Kept as `Store.RideWaivers` (texts in `waiver_texts`), one per signer+rider+bike per club day; honeypot + form token + 10/hour/IP. `MemberID` ties one to the member with that email (at signing, and `linkRideWaivers` on every new member, delete and startup). Admin: Waivers → First rides (per year, CSV), signed copy `/admin/ride-waivers/<id>` (board; Delete), and the member's page lists theirs.
- **Loaner bikes** (`loaners.go`, `Store.Loaners`; Rides → Loaner bikes, every admin): the fleet (`LoanerBike`: size, rider heights, bike, `Ready` = the Status select Available/Not available, saved on change; marking a reserved bike off warns `bike-held-off`; with none available the public pages stop offering loaners: `loanersReady` template func (`Site.loaners`, set in `routes()`), the ride waiver's bike choice and Home's First Ride box, redrawn by `loanersChanged`; seeded once with XS 2017 Trek Domane 47 cm and XL 2018 Cannondale Synapse 61 cm ready, M and L empty). Every group ride on the road (not events, virtual, cancelled or waiting rides) shows the ready bikes on its page until 8 pm the day before (`loanerOpen`); taken ones say Reserved. `/calendar/ride/<key>/loaner` is the ride-waiver template in loaner mode: bike, name, email, loaner waiver signed with it (`rideWaiverForm`), 5/hour/IP. A waiting or confirmed request holds that bike for that ride (`bikeHeld`); the club inbox hears of it (`clubNotice`: in the Morning summary unless the ride is today or tomorrow), admins with alerts on get a Confirm / Look first alert, and Home shows it; admins Confirm / Decline (optional reason) / Cancel, and the rider gets a `mailLoaner` email each time. A bike held for a ride coming up can't be removed.
- **Strava import:** admin Rides → Connect Strava (needs a Strava API app: callback domain = site host, one athlete, paid subscription on the owning account). Hourly sync of club events (reads them like Strava's apps do, not a documented API), daily past-events import (admin Ride history, and how often each route is ridden: `ClubRoutes` fills the ride forms' Route box). The public Club Routes page was removed (2026-11). Private Strava events are shown in full (notes, start address): the club makes them private only to keep bots out. Private Strava routes stay hidden.
