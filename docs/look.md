# Look and layout (public site and admin)

Detailed notes moved from CLAUDE.md. Read the section for the feature you are changing; keep it current when behaviour changes.

- **Look** (site.css top): headings (`h1`, `h2`, home `###`) in Barlow Semi Condensed 600/700 (`--display`, self-hosted woff2, OFL), body Poppins; spacing steps `--space-xs`…`--space-3xl`. Colour, corner, shadow and ring tokens live once in `web/static/tokens.css`, which site.go puts in front of both site.css and admin.css (site.css keeps only layout tokens: `--max`, `--pad`, `--side`, fonts, `--label`, spacing); admin.css re-sets only the few shades it always drew its own way (`adminOwnTokens`), and `TestTokensShared` fails if either file sets any other shared token. Tokens, not hex: `--muted`, `--field` (input edges), `--tint`/`--tint-2`/`--band`/`--ph`, status `--ok|err|warn` with `-bg`/`-ink`, corners `--r-sm` 6 / `--r-md` 8 / `--radius` 10 / `--pill` (never `--r`: focus.go uses it), `--shadow-1|2|pop`, `--ring`. Every field gets one zero-weight rule (`:where(main) :where(input…,select,textarea)`: focus ring, disabled, `:user-invalid`); checkboxes/radios are red. Buttons: `.btn`, `.btn-quiet`, `.btn-sm`, `.link-button`. Messages: `.cal-msg` (green, check), `.cal-err` (red, !), `.cal-note` (amber); `.empty`, `.muted`, `.tag`. Home: the hero fills the screen on phones (`100svh` minus the header) and about two thirds of it from 768px (68svh, 460–780px) with an uppercase headline; from 1100px it shows the next ride in its corner (`hero-next`, `view.NextRide` = first uncancelled `Upcoming`), each band puts its `.band-head` (label + heading, wrapped in content.go so a missing label changes nothing) left and its first paragraph right (Become a Member: words left, plans right), Next Rides is one row of 4, a heading with no paragraph takes the full width, the photo row shows 4 at a time, Ride With Us / Giving Back put each photo beside its words (same height), Instagram's heading sits beside square posts, the footer puts link columns and sponsors on one row; bands ~72px apart on phones, ~48–72px on computers, text ≤36rem; from 1440px the root font grows (17px, 18px and `--max` 1320px at 1900px); Ride With Us / Giving Back and the photo row are flat (no cards, square corners). Pages are a centered `.page` column (840px; `.page-wide` 1100px); form pages (join, membership, ride waiver/loaner, calendar/new, share photos, unsubscribe, RSVP) add `.page-narrow` (36rem) so title, notes and form share both edges; don't cap boxes narrower inside a page. **Computer layouts** (site.css end, phones keep one column in the same order): ride pages (`ride-page`) put details (`ride-a`, `ride-b`) left and Who's going / RSVP (`ride-side`) right from 1100px; a `fold: yes` page with 3+ sections gets a contents list on the left from 1200px (`Page.Sections`, `.toc`, current section marked by site.js); the calendar is 1440px with Coming up in a right column from 1280px (`cal-main` wraps the month), ←/→ change month; Join puts title and perks left, form right from 1100px (`join-page`); gallery and albums 1400px (`page-gallery`). From 768px the footer adds link columns (`ftr-links` in layout.html: Rides, Club = the Info menu's `infoLinks`, Members) and drops its My Membership / Ride Waiver links; ride cards lift on hover; nav text 15.5px from 1440px. A `^^ Label` line right above a `##`/`###` heading renders `<p class="label">` over it (content.go). The hero video pauses when under 15% of it is on screen (site.js).
- `web/templates/*.html` (admin: `admin.html` holds only the frame: `head`, `foot` and the shared scripts; every screen lives in its area's `admin-<area>.html` (app, access, home, members, mail, email, newsletter, rsvp, rides, pages, gallery, website, kit, treasurer), and site.go loads all `admin*.html` as one set, so a new area file needs no Go change; admin pages allow inline scripts, so moving one changes no CSP hash), `web/static/site.css` (colors at top), `site.js` (also the stats beacon), `web/static/img/` (logo, favicon, og). `web/waiver.html` and `web/waiver-guardian.html` are legal text copied from the League of American Bicyclists: change only for a new League version; `web/waiver-loaner.html` is the club's own loaner bike agreement (insurer or lawyer approves changes); signed waivers keep their original text (`waiver_texts`).
- **Admin look** (`web/static/admin.css` top, `foot` script in admin.html): the dark `.bar` is sticky and slides away on scroll down (`bar-hidden`; pinned rows use `top:var(--bar-top)`), since iOS 26 home screen apps colour the status bar from a pinned top bar and ignore `theme-color` (an unpinned bar showed faded under it). tokens on `:root` (`--radius` = `--r-sm`, `--r-md`, `--radius-lg`, `--pill`, `--field` (input border), `--card`, `--tint`/`--tint-2` beige fills, `--ok`/`--err`/`--warn` with `-bg` and `-ink`, `--ring`, `--shadow-1`, `--shadow-2` (hover), `--shadow-pop`; names match site.css, no `--r` token (`--r` is the framing clip radius)): use them, not typed-out colours. Sideways-scrolling menu rows fade at the edge with more (`more-l`/`more-r`); a group with one section shows no sub row. Three button kinds: primary (`button`/`.btn`, solid red), secondary (`.ghost`), list actions (`.link`, `.link.danger`); all lift on hover, press down, show `--ring` on keyboard focus, fade when disabled. Buttons drawn as something else (`.auto-open`, `.framer-open`, `.switch`, sort headings…) are listed in one `:is(...)` rule that keeps them flat. Feedback: any form send marks its button `.is-busy` (spinner, double sends ignored, reset on back/after 15 s) unless the form's own script stopped the send; the green "Saved" toast closes on click/Escape; errors (`.flash.err`, shake) and warnings (`.flash.warn`) have icons; `:target` rows glow (Undo links use `#id`). `[hidden]` always hides. In the admin app the server draws `.app-top` instead of `.bar` (`InApp`, appframe.go; docs/website.md); both are sticky with `bar-hidden`. **Building blocks** (admin.css, after `.card`; use them before writing a one-off): `.card` (box of fields), `.box` (flat card for read-only blocks: waiver copy, saved-meeting note), `.field` (small label over its field) in a `.field-row` (auto-fit columns, `min(100%,11rem)`, gallery tools, photo review), `.facts` (`dl` label/value list, pairs may be wrapped in a `div`; stacks under 480px: member details, waiver, automations), `.rows` (list whose `li` ends in an `.act-row` of buttons that drops under the words under 600px; Needs attention is `rows todo`, the app's Needs you uses `act-row app-acts`), `.wrap-row` (a line that wraps, was `.send-row`; a direct `input` grows, at least `min(100%,13rem)`). Don't reuse `.acts`: it is the table action column. `TestAdminRetiredClasses` fails if a replaced one-off (`send-row`, `todo-acts`, `when-row`, `auto-facts`…) comes back. **Phones** (admin.css end): fields are 16px on touch screens (iPhones zoom into smaller ones); list tables with `class="stack"` read as one block per row on phones (`td.lead` first, `td.acts-cell` last), tables with `cards` keep a label column; every grid column is `minmax(0,…fr)` and every fixed minimum `minmax(min(100%,…),…)` (`.card` included), since a plain `1fr` grows to its widest content (a long email, a file picker, a select's longest option) and `.wrap`'s `overflow-x:clip` then cuts it off; `TestAdminGridsShrink` fails on a plain one. **Run-off check** (`tools/runoff.js`, no installs): on a `-demo` preview, sign in, open any `/admin` page and paste the file into the browser console (or run it with the preview's JavaScript tool); it follows `/admin` links from Home and the app Home (one page per kind, GET only), loads each as a 320px and 375px frame in the normal admin and the app frame (it switches `pv_app` with `?app=0|1` and puts back the one you were in), and prints a table of every element past the screen's edge that isn't inside a sideways scroller; an empty table means nothing runs off. Run it after any admin layout change. Under 480px `cards` tables put each label over its value. **No explanatory text** on admin screens (Karl's rule): only labels, data, tooltips (`title`), short empty states ("No albums yet.") and real alerts (test mode, errors, things needing attention); the How the site works page is where explanations live.
- **Drag bars** (`foot` template in admin.html): every preview window (email, automation list, newsletter email, page editor) and anything with `data-resize="name"` gets a `.drag-bar` under it: drag or arrow keys resize, double-click resets; height kept per kind in localStorage (`h:<kind>`). A hand-set height stops `initMail` from fitting the frame to the email.
- **CSP hashes** (`csp.go`) are taken with line breaks as `\n`, like browsers, so a Windows checkout (CRLF) runs the site's scripts too.
